고치고, 교정하고, 검토하고, 요약하고, 다른 형식으로 옮기는 스킬이 여기 모인다. 지금은

| 스킬 | 하는 일 |
|---|---|
| `document:writing-post` | 블로그 글을 다섯 단계 절차(ABT → 뼈대 → 초고 → 세 번 퇴고 → 제목·summary)로 쓰거나 고친다. 단계마다 완료 조건이 있고, 한국어 문장 교정표가 붙어 있다 |

## writing-post — 블로그 글 쓰기·고치기

### 사용법

- 자연어: "이 프로젝트 소개글 써줘", "이 글 다듬어줘", "퇴고해줘" (모든 CLI 공통)
- 명시 호출: `/writing-post <mdx 경로 또는 소재>` (충돌 시 `/document:writing-post`) — Claude Code 전용

### 동작

1. 프로젝트의 글 규격 문서(`AGENTS.md`, `docs/agents/*.md` 등)를 먼저 읽는다 — 프론트매터·summary·빌드 검사·어조 같은 프로젝트 규칙이 스킬보다 우선
2. **자료와 갈등** — README·커밋·코드·메모·사진을 읽고, 자료가 답하지 못하는 것만 사용자에게 묻는다(한 번에 세 개 이하). 상황(무엇을 했나)과 이야기(그래서 무엇이 달라졌나)를 구분하고 `~인데 · 그런데 · 그래서` 한 줄을 뽑는다. `그런데`를 찾을 수 없으면 초고로 가지 않고 묻는다
3. **뼈대** — 소제목만 읽어도 논증이 따라오게 짜고, 여는 방식(장면·고백·사람·자격·오해 차단·명제)과 끝의 유형(낮추기·행동·되돌아와 넘기기), 이미지·코드의 자리를 정한다
4. **초고** — 다듬지 않고 끝까지. 사례가 원칙보다 먼저, 주장은 틀리지 않는 선에서 가장 세게, 버린 대안은 한 줄로
5. **퇴고 세 번** — 구조(빼면 안 통하는가) → 문장(한 줄 한 문장, 주어-동사) → 한국어([교정표](skills/writing-post/reference/korean-sentences.md), 사용자의 말버릇은 건드리지 않음)
6. **제목·summary·저장** — 제목은 본문이 지키는 약속. 규격대로 파일을 쓰고 프로젝트 검사 명령이 있으면 실행. 커밋·배포는 사용자가 시킬 때

요청한 만큼만 한다 — "문장만 다듬어줘"면 5단계(퇴고)만 밟고 구조는 건드리지 않는다. 사실은 확인할 수 있는 자료에서, 이유와 감상은 사용자에게서만 가져온다. 자료에 없는 이유는 채우지 않고 묻는다. 끝나면 ABT 한 줄, 바꾼 이유, 남긴 질문, 검사 결과를 짧게 보고한다.
